**4. Architecture**

**6. Founder Baseline**

Use a project compartment and clear ownership, with separate production and nonproduction boundaries before live customer traffic. Keep tenancy administration exceptional; give routine deployers narrowly scoped access. Do not introduce `manage all-resources` or user API keys inside containers.

Apply consistent `project`, `environment`, `owner`, `managed-by` and `expires-at` tags. Inspect the exact budget target before proposing another budget. Budgets provide alerts, not spending caps; use supported quotas only after verifying their scope and enforcement.

**8. Verification, rollback and teardown**

Success requires more than an HTTP response:

- HTTPS `/healthz` returns the expected response through the intended gateway; direct public access to the container is unavailable.
- Gateway and container evidence correlate with a test request. Required application logs are searchable for the chosen retention period through a verified ingestion path.
- Metrics show workload activity, and a controlled alarm reaches a monitored destination.
- Ownership tags and the budget target cover the deployed resources.
- The image digest matches the release, and image access has the intended scope.
- If secrets or PostgreSQL are introduced, test actual retrieval and a minimal database transaction. Environment-variable presence is insufficient.
- Validate capacity, restart and replacement behavior against the agreed availability target before production.

For application rollback, retain the previous image digest, configuration and compatible infrastructure revision. Reapply the reviewed prior release to the exact environment and repeat verification. Do not promise zero downtime from a single instance.

Keep database changes backward-compatible across the rollback window. A code rollback cannot undo an incompatible migration or recover deleted records; use a separately tested restore/cutover plan.

For teardown, identify resources from the exact Terraform state and deployment receipt, distinguish managed resources from read-only dependencies, preview destruction and settle backups/retention first. Obtain separate destructive approval. Check images, logs, secrets, DNS, certificates, addresses, backups, subscriptions and state storage for residual ownership and charges. Completion requires confirmed absence of intended targets and an explicit inventory of retained resources.
